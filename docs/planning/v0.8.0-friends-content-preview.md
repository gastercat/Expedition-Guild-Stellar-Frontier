# v0.8.0 Friends Content Preview Planning

## Purpose

This document is the internal planning note for the v0.8.0 Friends Content Preview. It records the intended order, risks, and validation rhythm before any candidate content mod is added.

Every candidate still requires Inventory-first review and Experience-filter review before installation. This is not approval to install all listed mods.

## Scope

v0.8.0 should add friend-visible content in small, testable steps:

- Multiplayer loot improvements.
- More weapon and relic variety.
- More exploration hooks.
- More base life, furniture, and companion flavor.
- Better reasons for 2-4 players to travel, loot, prepare, and report back together.

Early v0.8.0 work should prefer:

- One mod at a time.
- Install verification.
- JEI and item ID scans.
- Simple FTB Quests introductions.
- Player-facing documentation.
- Manual multiplayer testing before deeper integration.

## Non-goals

v0.8.0 Phase 0 and early Phase 1 are not for:

- Blind install-all content stacking.
- Full questline integration for every candidate mod.
- Large KubeJS systems.
- New GameStages logic.
- Recipe rewrites.
- Loot table rewrites.
- Boss balance passes.
- Economy, auction, pets, minions, or real skill XP systems.
- Full v0.9.0 class identity expansion.
- Full v1.0.0 campaign coherence work.

## Candidate content order

Recommended first-pass order:

1. Lootr
2. Simply Swords
3. Artifacts
4. Dungeon Crawl
5. Macaw / furniture / base life
6. Touhou Little Maid
7. Twilight Forest
8. Terramity

This order favors low-risk multiplayer experience improvements before high-risk dimensions, bosses, worldgen, and broad balance changes.

## Per-mod risk notes

### Lootr

- Risk: low/moderate.
- Main concern is multiplayer loot behavior and whether chests feel fair in shared exploration.
- Good first candidate because it improves the friends experience without redefining the campaign.

### Simply Swords

- Risk: moderate.
- Adds weapon variety, but may affect combat difficulty and class identity.
- Needs item availability and loot source review before broad use.

### Artifacts

- Risk: moderate/high.
- Relics can create strong passive power spikes.
- Needs loot table and progression review before being treated as normal campaign rewards.

### Dungeon Crawl

- Risk: moderate/high.
- Adds exploration, worldgen, and loot pacing risk.
- Needs new-world testing and server performance checks before quest integration.

### Macaw / furniture / base life

- Risk: low/moderate.
- Mostly building, decoration, and recipe testing.
- Best used to make the guild base and shared outposts feel more alive.

### Touhou Little Maid

- Risk: moderate/high.
- Entity AI, multiplayer behavior, and server performance need careful testing.
- Should begin as flavor and companion research, not an automation backbone.

### Twilight Forest

- Risk: high.
- Dimension progression, boss order, loot, and quest integration can affect the whole campaign.
- Needs its own inventory-first research phase before adding it to the main progression.

### Terramity

- Risk: very high.
- Balance, bosses, loot, and calamity pacing may conflict with the current guild campaign.
- Should wait until the team has a clearer combat and reward baseline.

## Install one mod at a time rule

Install only one candidate mod or one tightly related mod family per phase.

After each install:

- Commit only the mod metadata and direct required files for that phase.
- Do not bundle multiple unrelated content mods.
- Do not add quests until the mod launches and basic items or systems are verified.
- Do not add KubeJS or GameStages integration until manual testing proves the content belongs in the campaign.

## Required validation after each mod

Minimum validation after each candidate install:

- `git status -sb`
- `packwiz list`
- Confirm packwiz metadata changes are limited to expected files.
- Launch the pack.
- Enter a test world.
- Open FTB Quests.
- Open JEI and search for candidate content.
- Check latest log for ERROR or FATAL entries.
- Run a short 2-4 player test when multiplayer behavior matters.
- Record whether players understand what the new content is for.

For worldgen, dimension, entity AI, or loot mods, also validate:

- New world generation.
- Server performance.
- Chunk loading behavior.
- Loot fairness.
- Crash recovery.
- Whether the content appears too early or too strong.

## Rollback notes

If a candidate causes crashes, broken worldgen, severe balance issues, or unclear player experience:

- Stop before adding quests or integration logic.
- Do not stack another mod on top of the issue.
- Revert the candidate in a dedicated rollback phase if needed.
- Keep notes on what failed and whether the candidate should be retried later.

Avoid manual packwiz hash editing unless there is no safer alternative and the user explicitly approves it.

## When to stop and ask for approval

Stop and ask before proceeding if:

- More than one candidate mod would be installed in the same phase.
- A candidate requires KubeJS, GameStages, recipes, loot tables, or config changes to be usable.
- A candidate changes boss progression, dimension progression, or major loot pacing.
- A candidate creates unexpected packwiz metadata changes.
- A candidate introduces crashes, severe lag, or multiplayer desync.
- The content feels powerful but does not clearly support the guild campaign experience.
